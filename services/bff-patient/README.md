# @endo/bff-patient

**Purpose:** backend-for-frontend for `apps/patient-web` (spec 8.2, 8.4). Holds sessions and service tokens server-side; the browser only ever has an `HttpOnly`, `Secure`, `SameSite=Strict`, `__Host-` session cookie.

**Owners:** patient experience team; auth changes need security review.

## Public API (HTTP)

| Route                             | Auth                                       | Purpose                                                                                                                                                                                                                                                                                                    |
| --------------------------------- | ------------------------------------------ | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `GET /healthz`                    | public (liveness)                          | Liveness                                                                                                                                                                                                                                                                                                   |
| `GET /v1/hello`                   | session                                    | M0 walking skeleton: proves BFF -> API -> authz -> audit                                                                                                                                                                                                                                                   |
| `POST /v1/enrolment/start`        | enrolment (before an account)              | ADR-0021: start enrolment with the link token (from the URL fragment, posted by the page). Sets `__Host-endo_enrolment` (Secure, HttpOnly, SameSite=Lax, expires at the transaction's absolute deadline). Returns the code once. Exact Origin and a JSON body required; 10 starts per client IP per minute |
| `GET /v1/enrolment/status`        | enrolment cookie                           | Her transaction's state, never the code. Once it is `active`, her consent-pending session rotates into a patient session (new token) and the enrolment cookie is cleared; once it is cancelling, the consent-pending session ends (ADR-0021 section 12)                                                    |
| `POST /v1/enrolment/cancel`       | enrolment cookie                           | She cancels; clears the cookie. Exact Origin and a JSON body required                                                                                                                                                                                                                                      |
| `GET /auth/enrolment/callback`    | enrolment cookie                           | Keycloak's return after her first passkey. A valid ID token for this browser's attempt, accepted by the coordinator, creates a fresh consent-pending session (`__Host-endo_session`, Strict, at most 60 minutes)                                                                                           |
| `POST /v1/enrolment/consent`      | enrolment cookie + consent-pending session | Her four decisions; only her consent-pending session for this transaction may send them                                                                                                                                                                                                                    |
| `POST /v1/session/sign-out`       | none (exact Origin)                        | Ends whichever session this browser holds                                                                                                                                                                                                                                                                  |
| `GET /auth/sign-in`               | none (starts sign-in)                      | REQ-001: a returning patient signs in with her passkey. Authorisation code with PKCE; the attempt is bound to `__Host-endo_signin` (Lax, 10 minutes)                                                                                                                                                       |
| `GET /auth/callback`              | sign-in cookie + state                     | Validates the ID token, asks the identity service for her patient record, then creates a fresh patient session (Strict) and returns a same-origin page. Every refusal is the same 401                                                                                                                      |
| `GET /v1/session`                 | session (also when locked)                 | Whether she is signed in, whether the session is locked, and her app-lock choice; never her ids                                                                                                                                                                                                            |
| `POST /v1/session/app-lock`       | session (unlocked), JSON body              | Spec 10.1: turns app lock on or off. With it on, a session unused for 5 minutes locks itself                                                                                                                                                                                                               |
| `POST /v1/session/lock`           | session, JSON body                         | The page calls it when she leaves the app; locks only if app lock is on. A locked session is refused everywhere (`authn.locked`) except here and `GET /v1/session`; she unlocks by signing in again with her passkey, which keeps her app-lock choice (same person only)                                   |
| `POST /v1/settings/email`         | session (unlocked), exact Origin, JSON     | ADR-0026: sends a code to a new address for her sign-in fallback; the person comes from her session, never the request                                                                                                                                                                                     |
| `POST /v1/settings/email/confirm` | as above                                   | Confirms the address with that code; it then becomes her sign-in fallback address                                                                                                                                                                                                                          |

## Current state (M0)

- Sessions: `DevSessionStore` only, refused outside dev/test (the durable store is in the infrastructure slice). It holds patient sessions and consent-pending sessions (ADR-0021 section 12); a consent-pending session never authorises an API call. Returning patients sign in with their passkey (`/auth/sign-in`); the email-OTP fallback is still to come (REQ-001).
- Unknown request fields are refused, never silently dropped (spec 12.3).
- CSRF: the enrolment routes run before any session exists, so they require the exact patient Origin and a JSON body, which a cross-site page cannot send without a CORS preflight this service never allows. Session-bound synchronizer tokens arrive with the first mutating session route.
- Enrolment is configured by `BFF_PATIENT_IDENTITY_BASE_URL`, `BFF_PATIENT_WORKLOAD_PRIVATE_KEY_JWK` and `BFF_PATIENT_ORIGIN` (all three, or none; without them the routes do not exist). Only SHA-256 hashes of the link token and the browser secret reach the identity service.
- Service-to-service mTLS is added by the infrastructure slice; service tokens are used now.

## Run locally

See the root README. `ENDO_ENV=dev`, `BFF_PATIENT_DEV_SESSIONS_ENABLED=true`; the process prints one synthetic session cookie to stdout.
